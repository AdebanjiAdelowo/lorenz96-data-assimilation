# Lorenz-96 Data Assimilation with an Ensemble Kalman Filter

A classical sequential-Bayesian-state-estimation study on the chaotic Lorenz-96 system: a stochastic
Ensemble Kalman Filter (EnKF) is derived from the mathematics, independently validated against the
exact Kalman filter on a linear-Gaussian reference problem, then applied to a 40-dimensional chaotic
system under partial, noisy, intermittent observations. No machine learning is used anywhere in this
repository.

## Overview

The methodological arc is **chaotic dynamical system -> partial/noisy observations -> sequential
Bayesian state estimation -> ensemble covariance -> Kalman analysis -> forecast/analysis cycling ->
quantitative assimilation diagnostics**. Every stage is checked before being trusted for the next: the
Lorenz-96 model and integrator are verified before any assimilation work begins, chaos is quantified
(not merely observed) to establish *why* assimilation is needed at all, and the EnKF itself is
validated against an exact reference before being trusted on the nonlinear problem. Throughout, the
project follows the same standard used throughout this author's other computational-mathematics work:
negative or inconvenient results (filter divergence at
small ensemble size, the limits of localization, non-monotonic effects) are reported exactly as
measured, not tuned away.

## Lorenz-96 model

$$\frac{dx_i}{dt} = (x_{i+1} - x_{i-2})\,x_{i-1} - x_i + F, \qquad i = 0,\dots,K-1 \ (\text{cyclic}),$$

the standard minimal chaotic testbed for data assimilation (Lorenz, 1996; Lorenz & Emanuel, 1998).
**Configuration**: $K=40$, $F=8$ (the standard chaotic configuration used throughout the EnKF
literature), classical (non-adaptive) RK4 integrator, $dt=0.01$ model time units. Truth trajectories
are generated by spinning up from a generic initial condition for $t_{\text{spinup}}$ time units
(30 at `full` scale) before being used, so every experiment starts already on the chaotic attractor
rather than in an arbitrary transient.

**Verified before any assimilation work** (`tests/test_l96.py`, 10 tests):
- Cyclic indexing checked against an independent, non-vectorised Python-loop expansion for small $K$.
- $x_i = F\ \forall i$ confirmed an EXACT fixed point of the ODE, for any $F,K$ (substituting directly:
  $(F-F)F - F + F \equiv 0$) -- a genuine structural property, not an invented conserved quantity.
  A companion test confirms the FULL forced/dissipative system does NOT conserve
  $\sum_i x_i^2$ (only the quadratic term, in isolation, satisfies the exact identity
  $\sum_i x_i \cdot \big[(x_{i+1}-x_{i-2})x_{i-1}\big] = 0$, checked to machine precision), so this is
  never mistakenly assumed later.
- RK4 integrator convergence: order $3.9$-$4.0$ confirmed against a $dt=10^{-5}$ reference, across
  three step-size halvings.
- Deterministic reproducibility and bounded spin-up-to-attractor behaviour checked directly.
- A vectorised ensemble integrator (`integrate_ensemble`, used inside every EnKF forecast step) is
  checked to match per-member sequential integration exactly (used for a $\sim$14x wall-clock speed-up
  over a naive per-member Python loop, verified not to change any result).

## Chaotic dynamics

Quantified, not merely observed (brief section 3), via the classical Benettin et al. (1980)
renormalization algorithm for the largest Lyapunov exponent: integrate a reference and a perturbed
trajectory, periodically rescale the perturbation back to a fixed small norm, accumulate the mean
log-growth rate. Result (`scripts/estimate_lyapunov.py`, `full` config, $t_{\text{total}}=40$,
$\tau=0.1$):

$$\lambda_1 \approx 1.69 \quad (\text{running estimate: } 1.61 \text{ at } t=20 \to 1.69 \text{ at } t=40),$$

consistent with the commonly cited literature range for $K=40$, $F=8$ ($\lambda_1\approx1.6$-$1.7$
across sources using slightly different conventions). Validated internally: the estimate is
insensitive to the perturbation-norm scale (three widely different values, $10^{-4}, 10^{-6}, 10^{-8}$,
agree to 4 significant figures, confirming the algorithm operates in the correct locally-linear
regime) and stabilises rather than drifting over the second half of a long integration window
(`tests/test_chaos.py`, 4 tests). The e-folding (Lyapunov) time is $1/\lambda_1\approx0.59$ model time
units: a small initial error grows by a factor of $e$ roughly every 0.59 time units under free
integration -- this is the precise mathematical reason sequential assimilation, re-anchoring the
forecast to new data periodically, is needed at all (see "Free-forecast baseline" below for the
resulting error growth in RMSE terms). Perturbation growth and the running Lyapunov-exponent estimate
are plotted in `figures/lyapunov_full.png`.

## Observation model

$$y_k = Hx_k + \varepsilon_k, \qquad \varepsilon_k \sim N(0,R),$$

$H$ a $0/1$ selection matrix (observe every `stride`-th state component; `stride=1` = fully observed),
$R=\sigma_{\text{obs}}^2 I$ diagonal (`src/observations.py`). The EnKF analysis function
(`src/enkf.py:enkf_analysis`) takes only the forecast ensemble, the already-generated observation
$y$, $(H,R)$, and an RNG as arguments -- structurally unable to access the true state, checked directly
by inspecting its signature (`tests/test_enkf.py::test_filter_never_receives_true_state_directly`).

## Sequential state estimation

At each analysis time, the posterior (analysis) distribution given all observations so far is
approximated by an ENSEMBLE of $N_e$ state vectors rather than a single point estimate or an
explicit $K\times K$ covariance matrix -- the standard Monte-Carlo relaxation of the Kalman filter to
nonlinear, high(er)-dimensional systems where the exact Gaussian-linear recursion is unavailable.
One "cycle" = forecast (integrate every member forward to the next observation time) -> observe -> 
analysis (update every member using the ensemble's own sample covariance) -> repeat
(`src/experiment.py:run_assimilation_experiment`, reused unchanged by every study script in this
project).

## Ensemble Kalman Filter

**Stochastic EnKF with perturbed observations** (Evensen, 1994; the perturbed-observation correction
of Burgers, van Leeuwen & Evensen, 1998, which is what makes the ensemble-updated sample covariance an
unbiased estimator of the true Kalman-filter posterior covariance in expectation). Chosen over a
deterministic square-root filter (ETKF/EnSRF) because (a) it is the original, most direct
"derived-from-the-mathematics" formulation, and (b) its own Monte Carlo sampling noise is an explicit,
seed-controlled quantity this project's repeated-seed studies are specifically designed to
characterise (brief section 6) -- justified in full in `src/enkf.py`'s module docstring.

Forecast ensemble $X_f\in\mathbb R^{K\times N_e}$, mean $\bar x_f$, anomalies
$X_f' = X_f - \bar x_f\mathbf 1^T$. Working entirely in the anomaly representation (never forming the
$K\times K$ covariance explicitly):

$$Y_f' = HX_f', \qquad P_fH^T \approx \tfrac{1}{N_e-1}X_f'Y_f'^T, \qquad HP_fH^T \approx \tfrac1{N_e-1}Y_f'Y_f'^T,$$

$$K = (P_fH^T)\big[(HP_fH^T)+R\big]^{-1}, \qquad x_a^i = x_f^i + K\big(y^i - Hx_f^i\big),\quad y^i = y+\varepsilon^i,\ \varepsilon^i\sim N(0,R)\ \text{i.i.d. per member}.$$

## Independent linear-Gaussian validation

Before being trusted on the nonlinear L96 system, the EnKF was validated against the EXACT Kalman
filter on a small ($n=4$) linear-Gaussian system with a known analytical posterior
(`src/kalman_reference.py`, `tests/test_kalman_validation.py`) -- the data-assimilation analogue of
the analytical-posterior sampler check used for the pCN sampler in the companion
`darcy-inverse-problem` project. Both ensemble mean and covariance converge cleanly toward the exact
values as $N_e$ grows:

| $N_e$ | mean error (post-transient avg.) | covariance error (post-transient avg.) |
|---|---|---|
| 10 | 0.24 | 0.045 |
| 100 | 0.11 | 0.018 |
| 2000 | 0.02 | 0.004 |

roughly consistent with the expected $O(1/\sqrt{N_e})$ Monte Carlo convergence rate.

## Free-forecast baseline

A perturbed state (truth $+$ Gaussian noise, std 1.0) integrated FREELY, no observations ever
incorporated (`scripts/free_forecast_baseline.py`, `full` config): RMSE grows from $0.79$ at $t=0$ to
$3.86$ at $t=2$ to $5.22$-$5.26$ by $t=4$-$8$, saturating near the climatological RMS separation of two
independent attractor states (not a numerical artefact -- errors cannot exceed the attractor's own
scale). This is the baseline every assimilation result below must be judged against
(`figures/free_forecast_full.png`).

## Baseline assimilation

Fully observed, $N_e=20$ (deliberately modest for $K=40$, no localization/inflation), obs
std $=1$, observation interval $0.1$ time units, 400 cycles (`scripts/run_baseline_assimilation.py`,
`full` config):

- Time-averaged (post-transient) analysis RMSE: $4.47$ -- only marginally better than the free-forecast
  RMSE of $4.93$ at the same horizon.
- Time-averaged analysis spread: $0.19$. **Analysis RMSE / spread ratio $\approx24$** -- severe
  under-dispersion: the ensemble is confidently, persistently wrong.

**This is the central, honestly-reported finding motivating the rest of the project**: a plausible,
"reasonable-looking" ensemble size for a 40-dimensional system, without localization or inflation,
suffers textbook EnKF filter divergence (ensemble spread collapses while RMSE grows), demonstrating
directly the finite-ensemble sampling problem that localization and inflation exist to address --
motivated empirically here, not asserted (see "Localization" / "Inflation" below). Truth, observations,
and the EnKF analysis mean for representative state components are plotted in
`figures/baseline_components_full.png`; RMSE vs. time (analysis vs. free forecast) in
`figures/baseline_rmse_vs_time_full.png`; and spread vs. RMSE in
`figures/baseline_spread_vs_rmse_full.png`.

## Ensemble-size study

Same configuration, $N_e\in\{10,20,40,80\}$, no localization/inflation, 10 seeds
(`scripts/ensemble_size_study.py`, `full` config):

| $N_e$ | analysis RMSE (mean $\pm$ std) | spread (mean $\pm$ std) |
|---|---|---|
| 10 | $4.78\pm0.11$ | $0.145\pm0.003$ |
| 20 | $4.63\pm0.13$ | $0.184\pm0.004$ |
| 40 | $4.27\pm0.13$ | $0.218\pm0.007$ |
| 80 | $2.83\pm1.35$ | $0.234\pm0.005$ |

A clear improving trend, but even $N_e=80$ (double the state dimension) does not fully resolve the
problem without localization -- and its large standard deviation ($\pm1.35$) shows some seeds still
struggle. Larger ensembles alone are not assumed to fix every issue (confirmed, not assumed): see
"Localization" for the much larger improvement a modest ensemble gets from covariance localization
instead (`figures/ensemble_size_study_full.png`).

## Observation-density study

Vary observation stride at $N_e=40$ (a "moderately working" configuration, chosen so this effect is
visible without being swamped by the ensemble collapse the baseline demonstrates), 10 seeds
(`scripts/observation_density_study.py`, `full` config):

| stride | fraction observed | analysis RMSE (mean $\pm$ std) | spread (mean $\pm$ std) |
|---|---|---|---|
| 1 | 40/40 | $4.27\pm0.13$ | $0.218\pm0.007$ |
| 2 | 20/40 | $4.51\pm0.22$ | $0.355\pm0.007$ |
| 4 | 10/40 | $4.67\pm0.28$ | $0.625\pm0.027$ |
| 8 | 5/40 | $4.05\pm0.13$ | $1.959\pm0.071$ |

Density degrades performance from stride 1 to 4, as expected, with spread growing to compensate for
lost information (partially inferring unobserved components through the ensemble's dynamical
covariance). The stride-8 result is NOT monotonic with the trend (RMSE lower than stride 4, despite
observing only half as much) -- reported exactly as measured; this was not further diagnosed and is
listed as an open question in "Limitations" rather than smoothed over
(`figures/obs_density_study_full.png`).

## Observation-frequency study

Vary the interval between observations at $N_e=40$, stride 1, 10 seeds
(`scripts/observation_frequency_study.py`, `full` config):

| interval (time units) | analysis RMSE (mean $\pm$ std) | spread (mean $\pm$ std) |
|---|---|---|
| 0.05 | $3.84\pm0.39$ | $0.152\pm0.005$ |
| 0.10 | $3.56\pm0.43$ | $0.217\pm0.005$ |
| 0.20 | $3.24\pm0.49$ | $0.299\pm0.009$ |
| 0.40 | $2.91\pm0.37$ | $0.429\pm0.007$ |

At this $N_e=40$ operating point RMSE actually DECREASES slightly as the interval lengthens --
counter-intuitive at first glance, but consistent with the "Ensemble spread" finding below: this
filter is under-dispersive overall, and a longer forecast window between analyses lets the ensemble
anomalies grow closer to the actual forecast-error scale before the next (still somewhat overconfident)
analysis step, partially self-correcting the calibration rather than the physical assimilation
"working better." This is reported as measured, with this caveat, rather than as a straightforward
"less frequent observation helps" claim -- the relationship between frequency and quality is
confounded with calibration at this ensemble size, and a cleanly monotonic degradation would only be
expected for an already well-calibrated filter (e.g. localized)
(`figures/obs_frequency_study_full.png`).

## Noise sensitivity

Vary observation noise std at $N_e=40$, stride 1, interval $0.1$, 10 seeds
(`scripts/observation_noise_study.py`, `full` config):

| obs std | analysis RMSE (mean $\pm$ std) | spread (mean $\pm$ std) |
|---|---|---|
| 0.25 | $4.24\pm0.29$ | $0.050\pm0.001$ |
| 0.50 | $4.34\pm0.20$ | $0.104\pm0.002$ |
| 1.00 | $4.27\pm0.13$ | $0.218\pm0.007$ |
| 2.00 | $3.93\pm0.17$ | $0.468\pm0.008$ |
| 4.00 | $3.16\pm0.13$ | $0.969\pm0.017$ |

Lower observation noise does NOT automatically fix finite-ensemble covariance problems (checked
directly, not assumed): RMSE barely changes (and is not even monotonic) across a 16x range of
observation-noise variance at this $N_e$ -- the filter is limited by ensemble sampling error and its
own under-dispersion at this operating point, not by observation quality
(`figures/obs_noise_study_full.png`).

## Ensemble spread

Spread ($\sqrt{\mathrm{tr}(P)/K}$) tracked alongside RMSE throughout. Both this project's baseline and
ensemble-size studies show SEVERE under-dispersion (RMSE/spread ratios of 5-25) without localization.
The rank (Talagrand) histogram (`scripts/repeated_seeds_study.py`, localized filter, `full` config, 20
seeds, 38,400 truth/forecast-ensemble comparisons, `figures/repeated_seeds_full.png`) shows a clear
**U-shape**: counts at the extreme ranks (0 and $N_e$) are roughly $1.7\times$ the flat-histogram
expectation, confirming residual under-dispersion even AFTER localization has fixed the worst of the
problem. **A rank histogram is a diagnostic, not proof of calibration** -- it cannot detect a bias
shared by truth and ensemble, and this project does not claim formal statistical calibration anywhere,
only that spread and RMSE were compared and found consistently mismatched without localization, and
improved (though not perfectly flattened) with it.

## Localization

Applied BECAUSE the baseline demonstrated the need (severe under-dispersion at $N_e=20$ for $K=40$),
not by default. Gaspari-Cohn (1999) compactly-supported correlation function on the cyclic L96 ring
(`src/localization.py`), radius $\in\{2,4,6,10\}$ compared against no localization, $N_e=20$, 10 seeds
(`scripts/localization_study.py`, `full` config):

| radius | analysis RMSE (mean $\pm$ std) | spread (mean $\pm$ std) |
|---|---|---|
| none | $4.63\pm0.13$ | $0.184\pm0.004$ |
| 2.0 | $0.41\pm0.03$ | $0.354\pm0.002$ |
| 4.0 | $0.49\pm0.27$ | $0.289\pm0.002$ |
| 6.0 | $1.08\pm0.62$ | $0.260\pm0.003$ |
| 10.0 | $3.40\pm0.72$ | $0.227\pm0.003$ |

**Dramatic improvement**: radius 2 cuts RMSE by over $11\times$ relative to the unlocalized baseline.
Performance degrades smoothly as the radius grows toward the unlocalized limit (radius 10 is already
much worse), and the STANDARD DEVIATION across seeds also grows with radius -- weaker localization
means occasional bad seeds re-emerge, not just a worse mean. The best radius differs slightly between
configurations (radius 4 best at `local` scale, radius 2 best at `full` scale) -- a modest,
seed-count-dependent effect reported honestly rather than papered over with a single "the" optimal
value (`figures/localization_study_full.png`).

## Inflation

Also applied only because under-dispersion was observed. A small a priori grid of multiplicative
inflation factors ($\lambda\in\{1.0,1.05,1.1,1.2,1.5\}$, NOT tuned against any single trajectory),
$N_e=20$, 10 seeds (`scripts/inflation_study.py`, `full` config):

| $\lambda$ | RMSE, inflation alone | RMSE, inflation + localization (best radius) |
|---|---|---|
| 1.00 | $4.63\pm0.13$ | $0.41\pm0.03$ |
| 1.05 | $4.51\pm0.16$ | $0.40\pm0.01$ |
| 1.10 | $4.40\pm0.09$ | $0.40\pm0.01$ |
| 1.20 | $4.20\pm0.11$ | $0.42\pm0.01$ |
| 1.50 | $3.16\pm0.63$ | $0.49\pm0.01$ |

**Inflation alone is a weak fix here**: even $\lambda=1.5$ (a large inflation factor) only brings RMSE
down to $3.16$, nowhere near localization's $0.41$ -- consistent with the diagnosed root cause being
spurious long-range sample correlations (a RANK/structure problem localization directly addresses),
not simply an underestimated variance SCALE (which is what inflation corrects). **Once localization is
already applied, additional inflation gives at most a marginal further improvement and then makes
things WORSE** (best at $\lambda\approx1.05$, degrading monotonically beyond that) -- over-inflating an
already-well-calibrated filter just adds unnecessary spread. The best-radius selection for the combined
study is computed empirically from this study's own small radius grid (not copied from a different
study or picked by an untested heuristic -- an earlier draft of this script picked the middle INDEX of
the radius list rather than the empirically best radius, silently conflating "radius 6" with "the best
radius"; caught and fixed before these results were produced)
(`figures/inflation_study_full.png`).

## Failure regimes

Actively searched for, per the brief (section 16): very small ensembles ($N_e\in\{4,6,8,10\}$), WITH
localization already applied (radius 4), 400 cycles (`scripts/failure_regime_demo.py`, `full` config):

| $N_e$ | analysis RMSE (time-avg.) | final spread |
|---|---|---|
| 4 | $4.05$ | $0.193$ |
| 6 | $3.65$ | $0.218$ |
| 8 | $2.91$ | $0.231$ |
| 10 | $0.89$ | $0.251$ |

**Localization does not rescue an extremely small ensemble**: $N_e=4$-$8$ remain badly degraded
(RMSE 2.9-4.1) despite localization, only recovering good performance at $N_e=10$. Extended runs at
$N_e=4$ (400+ cycles, no localization) show the filter settling into a STABLE but PERSISTENTLY WRONG
state -- spread collapses to $\sim0.05$-$0.12$ while RMSE plateaus near $5$ (essentially the
free-forecast scale) -- rather than literal numerical blow-up. This is reported as the project's
failure-regime finding because it is the MORE representative EnKF pathology in practice (a filter that
has become overconfident and stopped correcting itself), not because a numerical-overflow threshold
was ever triggered (`DIVERGENCE_RMSE_THRESHOLD=50` in `src/experiment.py` was never crossed in any
experiment in this project). RMSE and spread vs. time at every tested $N_e$ are plotted in
`figures/failure_regime_full.png`.

## Repeated-seed statistics

Because EnKF performance depends on the random initial ensemble and (for the stochastic formulation)
perturbed observations, no key comparison in this project rests on a single seed
(`scripts/repeated_seeds_study.py`, `full` config, 20 seeds, $N_e=20$):

| configuration | analysis RMSE (mean $\pm$ std) | per-seed range |
|---|---|---|
| unlocalized | $4.63\pm0.11$ | $4.43$-$4.85$ |
| localized (radius 4) | $0.43\pm0.20$ | $0.33$-$1.27$ (19/20 seeds in $0.33$-$0.62$) |

The localized filter's std ($\pm0.20$) is driven almost entirely by a single outlier seed (RMSE
$1.27$, vs. $0.33$-$0.62$ for the other 19) -- a concrete illustration of why $n>1$ seeds matter: a
single-seed report could easily have landed on either this atypically bad case or an atypically good
one, and either would have misrepresented the typical behaviour.

2 warm-up runs discarded, median of 5 timed repeats (`scripts/performance_benchmark.py`, `full`

| $N_e$ | median s/cycle |
|---|---|
| 10 | 0.00305 |
| 20 | 0.00317 |
| 40 | 0.00340 |
| 80 | 0.00384 |
| 160 | 0.00464 |

Sub-linear-looking growth in the tested range (dominated by fixed per-cycle overhead at these small
ensemble sizes, not by the $O(N_e)$ or worse ensemble-covariance cost, which only becomes visible at

well under 10 minutes), which is exactly what makes the 10-20-seed repeated experiments in every study
above affordable -- per the brief, prioritised over micro-optimising this already-fast code
(`figures/performance_scaling_full.png`).

## Limitations

- **Low-dimensional toy atmospheric model.** $K=40$ is a minimal caricature of one latitude circle,
  not a realistic NWP-scale state space (which would have $O(10^6)$-$O(10^8)$ dimensions and very
  different localization/inflation behaviour).
- **Perfect-model assumption.** The "truth" is generated by the SAME L96 model and parameters the
  filter uses; no model error is introduced. Real assimilation systems must additionally handle
  systematic model-truth discrepancy, which this project does not address.
- **Synthetic Gaussian observations only.** No real observational data, no non-Gaussian or
  non-additive observation-error models.
- **Localization/inflation are manually swept over small a priori grids, not adaptively tuned** (e.g.
  no adaptive inflation schemes such as RTPS/RTPP, no covariance-localization-radius optimisation
  beyond the small fixed grids tested).
- **Observation-density study's stride-8 non-monotonicity is unexplained.** Reported honestly (see
  "Observation-density study") rather than hidden; a full diagnosis (e.g. checking whether specific
  observed-node placement relative to the localization radius matters) was not pursued.
- **No parameter estimation.** $F$ and $K$ are fixed and known; the EnKF here estimates only the
  state, not any model parameters jointly.
- **Stochastic EnKF's own Monte Carlo noise is a genuine, irreducible source of run-to-run
  variability** (distinct from a deterministic square-root filter) -- explicitly characterised via the
  repeated-seed studies, not eliminated.
- **Single localization function (Gaspari-Cohn) and one inflation scheme (simple multiplicative)**
  tested; other established schemes (e.g. relaxation-to-prior-spread inflation, adaptive localization)
  were not implemented or compared.
- CPU-only; no distributed- or GPU-computing was implemented or benchmarked (not needed at this scale).

## Reproducibility

Every quantitative number in this README is written to a `results/*.txt` file (or `.npz` for the
baseline trajectory) by the script named alongside it; every figure is generated by that same script.
All random draws (initial ensembles, perturbed observations, Lyapunov-exponent perturbation direction)
use explicit, fixed, recorded seeds (`numpy.random.default_rng(seed)`); `tests/test_l96.py`,
`test_experiment.py`, and `test_enkf.py` check bit-for-bit determinism given a seed.

```bash
cd lorenz96-data-assimilation
pip install -r requirements.txt
pytest tests/ -v                                    # 40 tests, seconds

python scripts/estimate_lyapunov.py --config full
python scripts/free_forecast_baseline.py --config full
python scripts/run_baseline_assimilation.py --config full
python scripts/ensemble_size_study.py --config full
python scripts/observation_density_study.py --config full
python scripts/observation_frequency_study.py --config full
python scripts/observation_noise_study.py --config full
python scripts/localization_study.py --config full
python scripts/inflation_study.py --config full
python scripts/failure_regime_demo.py --config full
python scripts/repeated_seeds_study.py --config full
python scripts/performance_benchmark.py --config full
```

`configs/smoke.yaml` runs every script end-to-end in well under a minute total (coarse settings, not
representative results); `configs/local.yaml` gives moderate development-scale results;
`configs/full.yaml` (used for every number in this README) takes under 10 minutes total on the hardware
above.
